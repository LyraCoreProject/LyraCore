# Orchestrate the backlog

Work the agent-ready backlog as batches of subagent work while the maintainer keeps the merge seat. The orchestrator dispatches, grills, and relays; subagents read, decide small things, and build.

## 1. Settle session rules

Ask merge policy once, up front. Default from prior sessions: **PRs stay open, the maintainer merges**. Consequence: base dependent work on the open PR and flag the dependency in its description. The maintainer may pull issues mid-session ("X is being handled") — drop them and re-plan the batches.

## 2. Order the backlog

Pull the open `ready-for-agent` and `agent-safe` issues. Batch by dependency and subsystem:

- Same-subsystem issues become **one fan-out DAG**, never parallel sibling branches.
- Bugs that gate verification (hanging or broken test suites) go first.
- Anything needing production, a live realm, or a real client goes straight to the **operator bucket**, never into a batch.

## 3. Relevance check — at batch start, not upfront

Your own session's merges invalidate later issues, so check when the batch begins. One cheap read-only subagent per issue or cluster reads the issue, the git log, and the code:

- **Verifiably shipped** → close it with the evidence. Every triage comment starts with the exact line: `> *This was generated by AI during triage.*`
- **Partially shipped** → triage note stating exactly what remains; route the live half to the operator bucket.
- **`needs-live-eyeball`** → the repo convention: implemented issues stay open until a human confirms on a live client; the PR names precisely what to eyeball.
- For small bugs, combine check-then-fix in one agent: verify relevance, then either close with evidence or implement.

## 4. Spec and grill

Most agent-ready issues already carry briefs — spec only what is under-specified. The spec agent splits its open questions: **agent-settleable** (decide it, record the rationale) versus **maintainer judgment**. Surface judgment calls to the maintainer in compact grill rounds — concrete options, recommendation first — and adopt the defaults they wave through. Record landed terms in `CONTEXT.md`. When the maintainer asks for research ("how does X do it, do it better"), run it against primary sources before writing tickets.

## 5. Implement

Match ceremony to size:

- **Small** (one pass): one implement agent in an isolated worktree; PR via the `file-pr` skill.
- **Epic**: the `fan-out` skill. Tickets in `.claude/tickets/issue-<N>/`, committed on the feature branch so every agent can read them. Tracer runs alone on the strongest tier. Parallel slices get **explicit file ownership** in their briefs and push separate branches (`<epic>-tN`); an integrate step merges them before any slice that must see the union; the integration slice runs last and files **one PR**.

Every dispatch prompt carries the boilerplate in [AGENT-BRIEFING.md](AGENT-BRIEFING.md).

Model tiers: sonnet for checks, pattern-copy slices, and small fixes; opus for tracers, integration, specs, and privileged or production-adjacent paths. Record the tier on each ticket's `Model:` line.

Relay handoff notes agent-to-agent verbatim in the next dispatch — corrected constants, seam warnings, ordering constraints. When an agent reports a factual error in a ticket, fix the ticket file on the branch and confirm the correction back to the agent.

## 6. Close the session

- PRs for issues awaiting live verification link the issue with **no closing keyword**.
- Gaps the maintainer deferred become follow-up issues (with the disclaimer line).
- Wrap up with four lists: issues closed with evidence, PRs open for review, work remaining, and the operator bucket as a handoff.
